# 🚀 Подключение Backend к Frontend

## ✅ Что сделано

Backend полностью создан и готов к использованию:
- ✅ Express.js сервер с SQLite базой данных
- ✅ JWT авторизация
- ✅ REST API для всех сущностей
- ✅ CORS для кросс-доменных запросов
- ✅ Автоматическое создание демо-данных

## 📋 Инструкция по запуску

### Шаг 1: Установка зависимостей backend

Откройте терминал в папке проекта и выполните:

```bash
cd backend
npm install
```

Это установит:
- express - веб-сервер
- better-sqlite3 - база данных SQLite
- bcryptjs - хеширование паролей
- jsonwebtoken - JWT токены
- cors - кросс-доменные запросы
- dotenv - переменные окружения

### Шаг 2: Настройка переменных окружения

Создайте файл `.env` в папке `backend/`:

```bash
cd backend
cp .env.example .env
```

Отредактируйте `.env` и измените `JWT_SECRET` на случайную строку (минимум 32 символа):

```env
PORT=3001
JWT_SECRET=your-super-secret-random-string-at-least-32-chars-long
```

### Шаг 3: Запуск backend сервера

```bash
npm start
```

Вы увидите:
```
🚀 Backend сервер запущен на http://localhost:3001
📋 Демо-доступ:
   Админ: admin / admin123
   Сотрудник: employee / emp123
   Руководитель: ahmedov / lead123
✅ Demo data created
```

**Не закрывайте это окно!** Сервер должен работать постоянно.

### Шаг 4: Подключение frontend к backend

1. Откройте CRM в браузере
2. Перейдите в **Настройки → Подключение**
3. Включите **"Использовать серверный режим"**
4. Убедитесь, что URL сервера: `http://localhost:3001`
5. Нажмите **"Проверить"**
6. Индикатор должен стать **зелёным** (Подключено)

### Шаг 5: Тестирование

1. Выйдите из системы
2. Войдите снова (теперь через backend)
3. Создайте нового паломника
4. Откройте другой браузер (или режим инкогнито)
5. Войдите под другим пользователем
6. Вы должны увидеть того же паломника!

## 🔧 API Endpoints

### Авторизация
- `POST /api/auth/login` - вход
- `GET /api/auth/me` - текущий пользователь

### Паломники
- `GET /api/pilgrims` - список паломников
- `GET /api/pilgrims/archived` - архивные паломники
- `GET /api/pilgrims/:id` - получить паломника
- `POST /api/pilgrims` - создать паломника
- `PATCH /api/pilgrims/:id` - обновить паломника
- `POST /api/pilgrims/:id/archive` - архивировать
- `POST /api/pilgrims/:id/restore` - восстановить
- `DELETE /api/pilgrims/:id` - удалить

### Руководители
- `GET /api/leaders` - список руководителей
- `POST /api/leaders` - создать руководителя
- `DELETE /api/leaders/:id` - удалить руководителя

### Пользователи
- `GET /api/users` - список пользователей (только админ)
- `POST /api/users` - создать пользователя (только админ)
- `DELETE /api/users/:id` - удалить пользователя (только админ)

### Оплаты
- `GET /api/pilgrims/:id/payments` - история оплат
- `POST /api/pilgrims/:id/payments` - добавить оплату

### Квитанции
- `GET /api/pilgrims/:id/receipts` - список квитанций

### Журнал
- `GET /api/audit-logs` - журнал действий

### Здоровье
- `GET /api/health` - проверка работоспособности

## 🗄️ База данных

Backend использует **SQLite** базу данных (`crm.db` в папке `backend/`).

### Таблицы:
- `users` - пользователи системы
- `leaders` - руководители
- `pilgrims` - паломники
- `payments` - оплаты
- `receipts` - квитанции
- `audit_logs` - журнал действий

### Резервное копирование БД:

```bash
# Создать копию
cp backend/crm.db backend/crm.backup.db

# Восстановить из копии
cp backend/crm.backup.db backend/crm.db
```

## 🌐 Режимы работы

### Локальный режим (по умолчанию)
- Данные хранятся в localStorage браузера
- Работает без сервера
- Данные только на одном компьютере
- Нет синхронизации между устройствами

### Серверный режим
- Данные хранятся на сервере (SQLite)
- Доступ с любого компьютера в сети
- Реальная синхронизация в реальном времени
- Многопользовательская работа

## 🔐 Безопасность

### Пароли
- Хешируются с помощью bcryptjs
- Хранятся только хеши, не оригиналы

### JWT токены
- Выдаются при входе
- Действительны 24 часа
- Передаются в заголовке Authorization

### Разграничение доступа
- Администратор: полный доступ
- Сотрудник: доступ ко всем паломникам
- Руководитель: только свои паломники

## 🐛 Решение проблем

### Backend не запускается
```bash
# Проверьте, что порт 3001 свободен
# Windows:
netstat -ano | findstr :3001

# Linux/Mac:
lsof -i :3001

# Если порт занят, измените PORT в .env
```

### Frontend не подключается
1. Убедитесь, что backend запущен
2. Проверьте URL в настройках (должен быть `http://localhost:3001`)
3. Проверьте CORS в браузере (консоль разработчика F12)
4. Убедитесь, что firewall не блокирует порт 3001

### Ошибка "Недействительный токен"
- Токен истёк (24 часа)
- Войдите снова в систему
- Токен обновится автоматически

### Данные не синхронизируются
1. Нажмите "Синхронизировать сейчас" в настройках
2. Обновите страницу (F5)
3. Проверьте, что backend режим включен

## 🚀 Production deployment

Для развёртывания на сервере:

1. **Установите Node.js** на сервере
2. **Скопируйте папку backend** на сервер
3. **Установите зависимости**: `npm install --production`
4. **Настройте .env** с безопасным JWT_SECRET
5. **Используйте PM2** для управления процессом:
   ```bash
   npm install -g pm2
   pm2 start server.js --name crm-backend
   pm2 save
   pm2 startup
   ```
6. **Настройте Nginx** как reverse proxy
7. **Настройте SSL** сертификат (Let's Encrypt)
